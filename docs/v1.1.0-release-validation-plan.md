# SentinelFlow v1.1.0 Release Validation Plan

## 1. Purpose
This document outlines the validation procedures for the SentinelFlow v1.1.0 release. It ensures all features developed in the 43.x milestones operate flawlessly under near-production conditions, without security or regression failures.

## 2. Release Candidate Reference
- **Tag**: `v1.1.0-rc.1`
- **Branch**: `codex-sentinelflow-marketing-zentom-bot` (to be merged into `main`)

## 3. Validation Scope
Validation covers all SentinelFlow metadata, specifically focusing on Apex logic, LWC functionality, schema field level security, and overarching performance in the Command Center UI.

## 4. Features to Validate
The following newly integrated v1.1.0 features require specific validation checks:
- Native Approval Queue
- Native Action Center Queue
- Dashboard Filter UX
- Near-Realtime Telemetry Widgets
- Replay Export / Share
- Approval Escalation Indicators

## 5. Apex Test Plan
- Verify `ZentomDashboardControllerTest` passes all test cases successfully (14/14 coverage).
- Run full local test suite via `sf apex run test -l RunLocalTests -c -r human` to ensure no cascading regressions in previously existing SentinelFlow Apex classes.
- Ensure total Apex Code Coverage remains above 75%.

## 6. LWC / Manual Test Plan
- **Filters**: Test changing Status, Environment, and AI Confidence dropdowns to verify the list of incidents truncates dynamically.
- **Approvals**: Verify clicking 'Approve' correctly flags an incident for the Action Center.
- **Action Execution**: Verify an approved action triggers the execute mechanism and successfully creates an audit log + backend case.
- **Exporting**: Click "Export CSV" and "Copy Summary" on the Replay timeline and ensure output payload contains no secure tokens or raw payloads.

## 7. Security / Permission Checks
- Ensure FLS (Field Level Security) covers the newly introduced `Sentinel_Incident__c` statuses and fields (e.g., `Execution_Status__c`, `AI_Confidence__c`).
- Validate that regular analysts have read/edit capabilities required to clear incidents in the Approval Queue.
- Ensure the `ReplayExportData` wrapper correctly masks/removes raw payload data from the frontend.

## 8. Regression Checklist
- [ ] Ensure the overall dashboard still loads within < 2000ms.
- [ ] Incident Detection payload integration endpoints remain intact.
- [ ] Flight Recorder Timeline displays logs sequentially without timezone errors.

## 9. Go / No-Go Criteria
- **GO**: 100% of Apex local tests pass. Zero data leaks in export CSVs. UI filters respond correctly.
- **NO-GO**: Deployment validation fails, test coverage drops below 75%, or unresolved LWC syntax errors exist.
