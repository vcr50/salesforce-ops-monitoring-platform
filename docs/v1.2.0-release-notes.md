# SentinelFlow v1.2.0 Release Notes

This document provides the customer-facing and internal release notes for the SentinelFlow v1.2.0 Release Candidate.

---

## 1. Release Summary
SentinelFlow v1.2.0 delivers major enterprise updates to the operations monitoring platform, introducing real-time telemetry anomaly predictions via Zentom AI, a robust and safe Governed Auto-Heal execution engine, and real-time dashboard analytics tracking estimated savings.

---

## 2. Major New Features
- **Predictive Warning Console**: Zentom AI engine scans telemetry signals (CPU, API, Apex errors) in near-real-time to warn operators of potential outages before they affect business processes.
- **Governed Auto-Heal Engine**: Runs bounded recovery actions under strict security restrictions, enforcing mandatory approval queues for high-risk changes.
- **Value Realization Widgets**: Live glassmorphic metrics panel calculating MTTR improvements and estimated savings based on recovery successes.

---

## 3. Prediction Engine Updates
- **Adaptive Scoring**: Aggregates multi-source telemetry signals using calibrated, tuned weights.
- **Explainable Warning Cards**: Generates plain-text natural language summaries detailings anomalous behaviors and correlations.
- **Operator Feedback Actions**: Allows operators to calibrate scoring models dynamically by dismissing, marking noisy, marking useful, or linking warnings to active incidents.

---

## 4. Governed Auto-Heal Updates
- **Safe Recovery Boundaries**: Supports pre-approved, safe actions: `CREATE_CASE`, `CREATE_TASK`, `SEND_NOTIFICATION`, `RETRY_SAFE_INTEGRATION`, `UPDATE_SENTINELFLOW_STATUS`, and `RECOMMEND_RUNBOOK`.
- **Guardian Gate Policy Queue**: Incident scores $\ge 40\%$ automatically block execution. Human approval required for high-risk actions before any database changes are made.
- **Atomic Failure Recovery**: Automatically triggers Database savepoints and rollbacks on error, resetting parent incident fields to triage states and queuing async notifications.
- **Retry Ceiling Guard**: Limits automatic executions to a maximum of 3 failed attempts, blocking subsequent runs and logging a retry exhausted blockage.

---

## 5. Cost Savings Analytics Updates
- **Cost & Value Insights Dashboard**: Dynamic metrics showing Successful Recoveries, Avoided Case Count, Hours Saved, and MTTR Improvements.
- **ROI Calculations**: Estimates financial value using packaged metadata overrides for engineering hourly rates and support case costs to show estimated savings.

---

## 6. Security and Compliance Updates
- **Core Security Hierarchy**: Prediction recommends, policy controls, humans approve.
- **DML User Mode**: Enforces explicit database CRUD/FLS queries using `WITH USER_MODE` to secure transaction access.
- **Write-Once GRC Auditing**: Chronologically logs all transactions, approvals, failures, blocks, and rollbacks to `Sentinel_Audit_Log__c`.
- **Referential Integrity Fallback**: Preserves original IDs in trace fields even when parent incident records are deleted or locked.

---

## 7. Pilot Validation Results
The v1.2.0 Release Candidate completed all sandbox validation protocols successfully:
- **100% Test Success**: Deployed and passed all 422 unit tests with 0 failures on vjdev@asap.com.
- **Pilot Scenarios**: Passed all six controlled pilot scenario script runs, validating low-risk execution, unapproved high-risk blocks, destructive action compile-level locks, transaction rollbacks, retry ceilings, and compliance auditing.

---

## 8. Known Limitations
- **Anonymous Apex CLI Test Limits**: Test context boundaries (`Test.startTest()` / `Test.stopTest()`) are not supported in anonymous CLI runs and must be run as native Apex tests.
- **Async Notification Failures**: Slack and MS Teams webhook delivery failures schedule fallback email alerts asynchronously to prevent locking contentions on the database.

---

## 9. Deferred Items
- **Interactive Tuning UI**: SRE sliders for interactive parameter weighting adjustments are deferred to v1.3.0. Scopes are managed via custom metadata settings.
- **Autonomous Remediation**: Deprecated and deferred indefinitely. Safe operations are restricted to pre-approved case, task, recommendation, and retry paths. Fully automated self-repair is strictly prohibited.

---

## 10. Upgrade & Deployment Notes
- **Prerequisites**: Ensure users are assigned the `SentinelFlow_Admin` or `SentinelFlow_Operator` permission sets to enable the new FLS fields on incidents and predictions.
- **Custom Settings**: Adjust custom settings fields (`Engineering_Hourly_Rate`, `Manual_Resolution_Hours`) under `SentinelFlow_Setting__mdt` metadata to calibrate dashboard cost calculations for your organization.
