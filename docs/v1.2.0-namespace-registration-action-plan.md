# SentinelFlow + Zentom AI v1.2.0 - Namespace Registration Action Plan

This document defines Milestone 71B-3, the namespace registration and publisher setup action plan required before SentinelFlow can proceed to Managed 2GP package creation and Milestone 71C.

---

## 1. Purpose

The purpose of 71B-3 is to define the external Salesforce setup steps required to unblock AppExchange Managed 2GP packaging. This plan keeps package creation locked until the namespace is registered, linked to the Dev Hub, and reflected safely in project configuration.

No `sfdx-project.json` changes or package creation commands should run during this action-plan step.

---

## 2. Current Blocker

Current verified state:

- Dev Hub alias: `astrosoft`
- Dev Hub status: connected
- Existing package: `SentinelFlow`
- Existing package Id: `0HodL0000003WMjSAM`
- Existing package type: `Unlocked`
- `Organization.NamespacePrefix`: `null`
- `sfdx-project.json` namespace: blank
- Managed package: not created
- 71C status: BLOCKED

The blocker is not source-code readiness. The blocker is Salesforce packaging setup: a namespace must be confirmed and linked before creating the Managed 2GP package.

---

## 3. Required Namespace Decision

The release owner must decide and confirm the namespace prefix to use for the AppExchange managed package.

Required decision points:

- The namespace must be unique and suitable for AppExchange distribution.
- The namespace must be registered in the appropriate namespace org.
- The namespace must be linked to the Dev Hub through Namespace Registry.
- The namespace value must be the value later written into `sfdx-project.json`.
- The namespace decision must happen before `sf package create --package-type Managed`.

No managed package should be created while the namespace is unknown or blank.

---

## 4. Dev Hub / Partner Business Org Requirement

The AppExchange packaging path requires the correct Salesforce packaging account structure.

Required setup:

- Confirm the Partner Business Org or publisher account that owns the AppExchange listing.
- Confirm the Dev Hub intended for package creation is authorized for the publisher/AppExchange workflow.
- Confirm Dev Hub alias `astrosoft` is the correct Dev Hub for the managed package, or identify the correct Dev Hub alias before package creation.
- Confirm the namespace is available to the Dev Hub through Namespace Registry.

If `astrosoft` is not the final packaging Dev Hub, stop and rerun 71B namespace/package checks against the correct Dev Hub.

---

## 5. Namespace Org Requirement

A namespace must be registered in a namespace org before it can be linked to the Dev Hub.

Required namespace-org checks:

- Confirm the namespace org exists.
- Confirm administrative access to the namespace org.
- Confirm the intended namespace prefix is registered and active.
- Confirm the namespace is not already tied to a different package path that would conflict with SentinelFlow.
- Capture non-secret evidence of the namespace prefix for the release record.

The namespace prefix must be treated as permanent for the Managed 2GP package path.

---

## 6. Namespace Registry Linking Steps

Required linking flow:

1. Open the Dev Hub Setup UI for the intended packaging Dev Hub.
2. Go to Namespace Registry.
3. Link the namespace org that owns the selected namespace prefix.
4. Confirm the linked namespace appears in the Dev Hub namespace registry.
5. Re-run CLI verification against the Dev Hub.
6. Confirm a namespace value is available for `sfdx-project.json`.

Verification commands after linking:

```bash
sf org display --target-org <DEV_HUB_ALIAS>
sf package list --target-dev-hub <DEV_HUB_ALIAS>
sf data query --target-org <DEV_HUB_ALIAS> --query "SELECT Id, Name, NamespacePrefix FROM Organization"
```

If the CLI cannot expose Namespace Registry directly, use Setup UI evidence plus `sfdx-project.json` review and package creation validation as the confirming evidence.

---

## 7. AppExchange Publisher Setup Dependency

Managed 2GP packaging must align with the AppExchange publisher account.

Required checks:

- Confirm publisher profile is active.
- Confirm listing ownership path for SentinelFlow + Zentom AI.
- Confirm package namespace and Dev Hub are tied to the publisher setup expected for security review.
- Confirm who owns package creation credentials and who receives packaging error notifications.
- Confirm the final managed package package Id will be recorded in AppExchange readiness artifacts.

Without publisher alignment, a technically valid package may still be unusable for AppExchange submission.

---

## 8. sfdx-project.json Update Timing

Do not update `sfdx-project.json` until the namespace is confirmed and linked.

After confirmation:

- Set `namespace` to the confirmed namespace prefix.
- Add a new managed package alias.
- Keep the existing unlocked package alias as internal/historical reference only.
- Confirm `packageDirectories` points to `force-app`.
- Confirm future package version creation uses the managed package alias.

Do not reuse:

```json
"SentinelFlow": "0HodL0000003WMjSAM"
```

as the managed AppExchange package alias.

---

## 9. Managed Package Creation Timing

Run managed package creation only after namespace registration and Dev Hub linking are confirmed.

Approved future command:

```bash
sf package create \
  --name "SentinelFlow Managed" \
  --package-type Managed \
  --path force-app \
  --target-dev-hub <DEV_HUB_ALIAS>
```

After creation:

- Re-run `sf package list --target-dev-hub <DEV_HUB_ALIAS>`.
- Confirm package type is Managed.
- Confirm namespace prefix is populated.
- Add the managed package alias to `sfdx-project.json`.
- Commit the configuration change before 71C.

## 11. Risks

- Namespace cannot be changed after the managed package path is created.
- Creating a Managed 2GP package with the wrong Dev Hub or wrong namespace can force package rework.
- A blank namespace may create an invalid AppExchange security review path for the intended managed package.
- Reusing the unlocked package alias could confuse package lineage and audit evidence.
- Publisher account misalignment can block AppExchange submission even if package creation succeeds.
- Namespace-aware metadata may reveal package-compatibility issues that were not visible in the unlocked package path.

---

## 12. Final Unblock Criteria for 71C

71C can start only after all of the following are true:

- Namespace confirmed.
- Namespace linked to Dev Hub.
- `sfdx-project.json` namespace updated.
- New Managed 2GP package created.
- Managed package alias present.
- `main` is clean.
- No artifacts or secrets are in package scope.

Until those criteria are met, Milestone 71C - First 2GP Package Version Candidate remains BLOCKED.
