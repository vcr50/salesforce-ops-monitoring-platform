# SentinelFlow + Zentom AI — AppExchange Screenshots & Listing Assets

This document outlines the visual asset requirements, target UI screens to capture, overlay annotations, and design specifications for the SentinelFlow + Zentom AI AppExchange listing.

---

## 1. Graphic Asset Specifications

| Asset Type | Dimension (Width x Height) | Required Format | Purpose |
|---|---|---|---|
| **App Icon** | 60 x 60 px & 120 x 120 px | PNG (transparent) | Small and large brand icons used in Search & Listings |
| **Cover Image** | 1600 x 650 px | PNG or JPG | Banner displayed at the top of the AppExchange listing |
| **Promo Card (Small)** | 210 x 140 px | PNG or JPG | Grid tile card for Search result page |
| **Promo Card (Medium)**| 460 x 307 px | PNG or JPG | Featured app grids and category tiles |
| **Promo Card (Large)** | 724 x 348 px | PNG or JPG | Carousel marketing promotions |

## 2. Screenshot Inventory (Target Pages to Capture)

AppExchange requires a minimum of 4 and allows up to 12 screenshots. Recommended resolution is **1600 x 900 px** or **1280 x 720 px** (16:9 ratio) in PNG format with a consistent modern look.

### Screenshot 1: Command Center Dashboard
*   **Target UI**: The main dashboard console (`zentomDashboard.html`).
*   **Key Visual Elements**:
    *   Sleek glassmorphic layout showing the core telemetry widgets.
    *   Dark-mode KPI cards: Org Health Score, AI Confidence KPI, and Active Prediction Risk.
*   **Mock Annotation Callouts**:
    *   Circle the real-time CometD streaming metrics.
    *   Add a tooltip overlay pointing to the "Estimated Cost Savings" card, displaying: `Estimated Savings = (Cases Avoided * $120) + (Hours Saved * $150)`.
*   **Caption**: *"Real-Time Command Center: Monitor system health, streaming telemetry, and estimated operational value in a single glassmorphic pane."*

### Screenshot 2: Zentom AI Prediction Engine
*   **Target UI**: The active prediction warning cards and detail panel.
*   **Key Visual Elements**:
    *   Warning cards highlighting high-risk anomalies (e.g., Timeout spikes).
    *   Natural-language explanation templates explaining CPU, deployment, and error weight factors.
*   **Mock Annotation Callouts**:
    *   Highlight the risk scoring weight breakdown (e.g., `Timeout Weight: 45%`, `Deployment Event: 38%`).
    *   Point to the natural-language explainability block detailing why the warning was generated.
*   **Caption**: *"Proactive Risk Assessment: Zentom AI analyzes multi-signal telemetry to score incident risk with transparent, natural-language explainability."*

### Screenshot 3: Guardian Gate (Governed Auto-Heal)
*   **Target UI**: The Guardian Gate queue page and approval dialog.
*   **Key Visual Elements**:
    *   List of pending incident reviews.
    *   Action buttons: "Request Approval", "Dismiss", and "View Linked Incident".
    *   The "Request Approval" action drawer/popup demonstrating safe UX wording.
*   **Mock Annotation Callouts**:
    *   Highlight the mandatory approval gate for actions with risk scores $\ge 40\%$.
    *   Overlay text pointing to the action buttons: *"No bypass: High-risk operations require explicit human approval."*
*   **Caption**: *"Guardian Gate Approvals: Enforce absolute operational policy governance. High-risk actions remain blocked until explicitly approved by operators."*

### Screenshot 4: Accessible Settings UI
*   **Target UI**: The updated Settings page (`zentomSettings.html` or equivalent).
*   **Key Visual Elements**:
    *   High-contrast form fields, clean light-mode cards, readable select dropdowns, and webhook inputs.
    *   Active tabs displaying Threshold Config, Healing Rules, and Webhook Integrations.
*   **Mock Annotation Callouts**:
    *   Draw attention to the clean input fields showing configurable latency thresholds and active/inactive status toggles.
*   **Caption**: *"Simplified System Administration: Easily adjust detection thresholds, active healing rules, and webhook targets via a high-contrast, fully accessible interface."*

### Screenshot 5: Keyset Pagination Incident Grid
*   **Target UI**: The historical Incidents table showing pagination controls.
*   **Key Visual Elements**:
    *   Grid table displaying incident severity, correlation UUIDs, detected times, and MTTR counters.
    *   Infinite-scrolling loading spinner and cursor-based navigation controls ("Next Page", "Previous Page").
*   **Mock Annotation Callouts**:
    *   Annotate the page indicators: *"Infinite Keyset Pagination: Fluidly navigate millions of records without encountering Salesforce offset limitations."*
*   **Caption**: *"Infinite Data Scale: Keyset pagination handles large enterprise datasets with compound cursors, guaranteeing fast query response times."*

### Screenshot 6: GRC Trace Audit Trail
*   **Target UI**: The `Sentinel_Audit_Log__c` list view.
*   **Key Visual Elements**:
    *   Audit log rows showing UUID trace identifiers, action types, trigger contexts, and transaction hashes.
    *   A view-only detail panel verifying that operator write capabilities are blocked.
*   **Mock Annotation Callouts**:
    *   Circle the `Trace UUID` column.
    *   Overlay lock icons next to fields to illustrate write-once/read-only compliance enforcement.
*   **Caption**: *"Immutable Compliance Audits: Every execution, approval override, and failure state is locked in a write-once audit trail mapping to SOX and SOC2 requirements."*
