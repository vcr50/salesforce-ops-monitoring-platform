# v1.2.0 Release Candidate Scope Freeze

This document formalizes the scope freeze, completed features list, deferred features list, validation guidelines, security controls, and Go/No-Go checklist for the SentinelFlow v1.2.0 Release Candidate.

---

## 1. Purpose
The purpose of this document is to establish a strict feature freeze for the v1.2.0 package release. Under the freeze policy, no new feature creep or enhancements are permitted. The release team will focus exclusively on validation, critical bug fixes, security scanning adjustments, and package documentation.

---

## 2. Release Scope
The v1.2.0 release delivers two major enterprise enhancements to the SentinelFlow platform:
1. **Prediction Engine**: Real-time multi-signal telemetry ingestion, explainable risk scoring, and SRE feedback mechanisms.
2. **Auto-Heal Engine**: Bounded, governed operational recovery, Guardian Gate risk barriers, atomic savepoint rollbacks, retry ceilings, and write-once compliance logging.

---

## 3. Completed Features
- **SentinelPredictionEngine**: Dynamic telemetry processing correlating events, CPU spikes, and API errors into normalized scores.
- **SentinelPredictionExplanationService**: Plain-text natural language explanation card generator.
- **SentinelPredictionGovernanceService**: Action bindings for operator reviews, approval submissions, dismissals, and trust calibrators.
- **AutoHealExecutionService**: Core transactional recovery runner.
- **Guardian Gate Policy Queue**: Automatic approval gates blocking runs if risk $\ge 40.0\%$.
- **Fail-safe Rollback Logic**: Database savepoint transaction rollbacks.
- **Throttling Ceiling**: Retry cap preventing endless runs (capped at 3 failures).
- **GRC Compliance Logs**: Write-once entries in `Sentinel_Audit_Log__c` using Trace UUID correlation.
- **ROI Analytics Widget**: LWC cost savings metric widgets displaying MTTR and case cost metrics.

---

## 4. Excluded / Deferred Items
- **Autonomous Destructive Actions**: Database deletion, permission changes, and metadata edits remain strictly blocked in code and are deferred indefinitely.
- **Dynamic Weight Tuning UI**: Interactive slider UI for operator parameter weighting calibrations is deferred to v1.3.0. Calibrations are managed via custom metadata overrides or Apex overrides.
- **External Alert System Integrations**: Real-time Slack/Teams alerts use asynchronous future queue mockups; deep API handshakes are deferred.

---

## 5. Validation Requirements
- All local Unit Tests must execute and pass (`420/420` tests passing).
- Minimum Apex code coverage must exceed `95%` on new service classes.
- Validation scripts (Scenarios A through F) must execute cleanly with correct GRC decisions logged.

---

## 6. Security Requirements
- AppExchange Security Scanner (PMD/Checkmarx) must run on all classes with zero high-severity errors.
- Strict FLS/CRUD user mode enforcement (`WITH USER_MODE`) verified on all queries and mutations.
- Secret tokens, user passwords, and AI reasoning chains must be omitted from platform events.

---

## 7. Demo Readiness
- Storylines, visual assets, speaking guides, slide frameworks, objection lists, and QA scripts are completed under Milestone 63.
- Target sandbox (`vjdev@asap.com`) pre-configured with override parameters.

---

## 8. Known Limitations
- **CLI Test Limits**: Salesforce CLI anonymous Apex execution restricts test boundaries; simulation scripts run outside of test start/stop tags.
- **Future webhooks**: Webhook failures fail gracefully and generate logs asynchronously, preventing execution lock contentions.

---

## 9. Release Candidate Criteria

A release build will be promoted to Release Candidate (RC) status only when it satisfies these conditions:
1. **Zero High Bugs**: No open critical regressions.
2. **100% Test Success**: 100% pass rate on all unit tests.
3. **Security Clearance**: Successful static code scan without high-severity violations.
4. **Compliance Trail**: Complete UUID audit logging validated on all scenario script executions.

---
