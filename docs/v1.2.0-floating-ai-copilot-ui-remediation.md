# v1.2.0 Floating AI Copilot & Agentforce UI Remediation

This document records the UI remediation performed on the SentinelFlow + Zentom AI v1.2.0 packaging codebase to ensure a clean, compliant, and risk-free submission for the Salesforce AppExchange.

---

## 1. Context & Purpose

During final validation reviews, the floating chat interface and mascot avatar (`zentomCopilotMascot`) were flagged as an AppExchange demo risk. Specifically:
- **Visual Overlap**: The floating bubble overlapped dashboard widgets and charts on smaller resolutions.
- **Stuck Loading State**: The overlay modal remained stuck on the message `"Analyzing current page context..."` without a mock resolver.
- **Mock Live-Chat**: The interactive chat was not connected to a live streaming agent or backend websocket stream in the MVP layout.
- **Agentforce Terminology**: The UI contained explicit references to `"Agentforce"`, which is reserved for future release phases (Milestone 74) and must not be packaged in v1.2.0.

To remediate these issues, the floating chat component has been hidden by default, and all references to Agentforce have been replaced with Salesforce-native terminology.

---

## 2. Remediation Strategy

The floating assistant has been disabled at both the container layout and component levels, keeping the code intact for internal development preview while ensuring it is hidden from the packaged production UI.

### Hiding the Floating Assistant (71B-8)
1. **App Shell Flag**: Added a default feature flag `showZentomCopilot = false` inside `SentinelFlowBetaAppShell.js`.
2. **Layout Gate**: Wrapped the mascot markup in `sentinelFlowBetaAppShell.html` inside a conditional check:
   ```html
   <template if:true={showZentomCopilot}>
       <div class="sidebar-mascot-container">
           <c-zentom-copilot-mascot></c-zentom-copilot-mascot>
       </div>
   </template>
   ```
3. **Component Level Fail-Safe**: Set `isMascotEnabled = false` by default in `zentomCopilotMascot.js` to ensure the component renders blank even if instantiated.

### Agentforce Wording Removal
To align with the Milestone 74 roadmap, all UI-visible labels containing "Agentforce" were replaced:
- **Portal Copilot Panel**:
  - Badge updated: `"Zentom Gen AI + Agentforce"` &rarr; `"Zentom AI Core"`
  - Greeting text updated to omit execution claims:
    - *Before*: `"Zentom Gen AI handles reasoning and governance, while Agentforce executes trusted Salesforce actions."`
    - *After*: `"I can help you analyze telemetry, check logs, and recommend runbooks. How can I help you resolve incidents today?"`
- **Portal Login View**:
  - Feature description: `"Agentforce Copilot"` &rarr; `"Zentom AI Engine"`
- **System Telemetry Page**:
  - Indicator: `"Agentforce ready"` &rarr; `"Zentom AI ready"`
- **Architecture Diagram**:
  - Layer name: `"Agentforce"` &rarr; `"Salesforce Native"`
- **Theme Sidebar Mockup**:
  - Status indicator: `"Agentforce"` &rarr; `"Zentom AI"`
  - Footer label: `"Salesforce Agentforce"` &rarr; `"Salesforce Native"`

## 4. Verification Verdict (71B-9)

### Visual Smoke Test Outcomes
- **No Floating Bubble**: Checked app header, sidebars, and dashboard pages. The mascot avatar and chat bubbles are completely hidden from rendering.
- **No Dashboard Overlaps**: Layout margins, flex boxes, and grids render cleanly without any floating canvas elements blocking views.
- **No Stuck Spinner**: The stuck "Analyzing current page context..." loading spinner modal does not display under any scenario.
- **No Agentforce Wording**: Verified login screen, incident table details, and architecture tab graphs. All wording is aligned with Zentom AI core/native execution context.
- **Safe Chat UI**: The portal's embedded chat interface has been re-worded to refer strictly to advice, telemetry checking, and runbook recommendations without any autonomous self-healing execution claims.
