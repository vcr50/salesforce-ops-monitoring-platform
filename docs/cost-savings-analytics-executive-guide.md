# SentinelFlow Cost Savings & Value Insights Executive Guide

This guide provides an overview of the **Estimated Value Realization** dashboard widgets in the SentinelFlow Command Center. These metrics demonstrate the concrete, explainable business and operational value generated by SentinelFlow's autonomous healing capabilities.

To maintain trust with enterprise stakeholders and avoid misleading claims, all calculations are explicitly labeled as **"Estimated Savings"** (not guaranteed ROI) and are derived from configurable operational assumptions.

---

## 1. Metric Breakdown & Explainable Formulas

SentinelFlow measures value across five core widgets. Each widget features an interactive tooltip in the UI explaining the underlying math.

### A. Successful Recoveries
*   **What it means**: The count of production incidents that were self-healed or mitigated by SentinelFlow runbooks without human developer intervention.
*   **Underlying Formula**:
    ```
    Successful Recoveries = Count of Sentinel_Incident__c records where
                            Execution_Status__c = 'Executed'
    ```

### B. Estimated Hours Saved
*   **What it means**: Productive engineering time reclaimed by automating incident resolution instead of routing tickets to an active engineering queue for manual triage.
*   **Underlying Formula**:
    ```
    Estimated Hours Saved = Successful Recoveries × Manual_Resolution_Hours (default: 2.0 hours)
    ```

### C. Cases Avoided / Work Reduced
*   **What it means**: Incidents that were resolved autonomously *without* escalating or creating an external customer support case in Salesforce.
*   **Underlying Formula**:
    ```
    Cases Avoided = Count of Sentinel_Incident__c records where
                    Execution_Status__c = 'Executed' AND Created_Case__c = null
    ```
    *(Note: If a runbook execution logs an administrative case for tracking, that incident is excluded from Cases Avoided).*

### D. Estimated Cost Savings
*   **What it means**: The explainable dollar value saved from engineering time reclaimed and customer support ticket overhead prevented.
*   **Underlying Formula**:
    ```
    Estimated Cost Savings = (Hours Saved × Engineering_Hourly_Rate) 
                            + (Cases Avoided × Cost_Per_Support_Case)
    ```
    *   **Default Assumptions**: Engineering rate is $80/hr; Support Case overhead is $150/case.

### E. MTTR Improvement
*   **What it means**: The percentage reduction in Mean Time to Resolution compared to the manual historic baseline.
*   **Underlying Formula**:
    1.  *Actual Avg MTTR (Minutes)* = Average elapsed duration of `(Executed_At__c - CreatedDate)` in minutes for all `Execution_Status__c = 'Executed'` incidents.
    2.  *MTTR Improvement %* = `((Baseline_MTTR_Minutes - Actual Avg MTTR) / Baseline_MTTR_Minutes) × 100`
    *   **Default Baseline**: 240.0 minutes (4.0 hours).

## 2. Configuration for Administrators

Calculations do not use hardcoded permanent values. Administrators can customize all baseline parameters via Salesforce Setup to align with their organization’s actual costs:

1.  Navigate to **Setup** → **Custom Metadata Types**.
2.  Click **Manage Records** next to **System Setting** (`System_Setting__mdt`).
3.  Edit any of the following settings:
    *   **Engineering Hourly Rate** (`Engineering_Hourly_Rate`): Loaded cost per engineer hour (Default: `80.00`).
    *   **Manual Resolution Hours** (`Manual_Resolution_Hours`): Average hours to resolve an incident manually (Default: `2.0`).
    *   **Baseline MTTR Minutes** (`Baseline_MTTR_Minutes`): Historical MTTR baseline before SentinelFlow (Default: `240.0`).
    *   **Cost Per Support Case** (`Cost_Per_Support_Case`): Overhead cost of an escalated support case (Default: `150.00`).
