## 5. Permission / FLS / CRUD Summary

### What Was Validated

- **`SentinelFlow_Admin`**: Full CRUD on incident, prediction, and heal action objects. Read-only on `Sentinel_Audit_Log__c`. Kill switch and Custom Metadata access confirmed.
- **`SentinelFlow_Operator`**: Read-only on all 4 custom objects. Approve/reject access confirmed. No write, delete, or metadata management access.
- **FLS**: All sensitive fields restricted — operators cannot mutate OTS scores, resolution notes, execution status, or audit fields.
- **Audit Log**: Write-only via Apex system context (`without sharing` in `SentinelAuditLogger.cls`). Effectively read-only for all user-facing roles including admins.

### Privilege Escalation Assessment

| Path | Risk | Status |
|---|---|---|
| Operator → Admin escalation | None — separate permission sets, no overlap in write access | ✅ No escalation path |
| User → Audit log mutation | None — FLS+CRUD blocks all user-facing edits | ✅ No mutation path |
| API → Approval bypass | None — Apex code enforces approval check regardless of API caller | ✅ No bypass path |
