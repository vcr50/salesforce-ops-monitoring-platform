# Milestone 43D: Near-Realtime Telemetry Widgets Plan

## Goal
Make the Command Center feel more "live" and operationally aware by displaying trend widgets at the top of the dashboard. This will give users immediate visibility into system health and incident velocity.

## Strategy
To adhere to the "No full streaming yet" rule, we will:
1. **Leverage Existing Polling:** We will use the existing `refreshApex` / `@wire` polling mechanism that currently refreshes the dashboard data. 
2. **Derive from Existing Data (where possible):** Instead of creating heavy new SOQL aggregates, we will calculate some of these metrics client-side from the loaded payload or lightweight count queries.
3. **Last Refreshed Timestamp:** We will add a discrete "Last Updated: [Time]" ticker in the header to indicate the near-realtime polling status.

## Proposed Widgets (The "Telemetry Bar")
We will introduce a new row of compact telemetry widgets (likely above or alongside the existing KPI Tower Strip).

1. **Incident Volume Trend:** 
   - *Data:* Count of incidents created today vs yesterday, or just a sparkline of the last 7 days.
   - *Implementation:* Apex to return a lightweight aggregate of incidents by day for the last X days.
2. **Critical Incidents Trend:** 
   - *Data:* Number of Critical risk incidents over time.
   - *Implementation:* Filter existing data or lightweight aggregate query.
3. **Approval Queue Trend:** 
   - *Data:* How many incidents are pending approval right now.
   - *Implementation:* This already exists in `DashboardSummary.pendingApprovals`. We will visualize it as a live counter.
4. **AI Confidence Average:** 
   - *Data:* The average AI confidence score for recent incidents.
   - *Implementation:* Calculate client-side from the `recentIncidents` array or add a quick `AVG(AI_Confidence__c)` to the summary query.
5. **Case Creation Count:** 
   - *Data:* Number of service cloud cases generated by SentinelFlow executions today.
   - *Implementation:* Calculate from `Created_Case__c != null` records.
6. **Error Log Count:** 
   - *Data:* Volume of `Sentinel_Audit_Log__c` entries with error/failure status.
   - *Implementation:* Add an error count to the `getDashboardSummary` response.
7. **Last Refreshed Timestamp:** 
   - *Data:* Client-side JavaScript `Date.now()`.
   - *Implementation:* Updates every time the wired apex completes a refresh cycle, displaying "Last synced: 10:42 AM".

## Execution Plan
1. **Backend Updates (`ZentomDashboardController.cls`):**
   - Enhance the `DashboardSummary` wrapper class to include `avgAiConfidence`, `errorLogCount`, and `caseCreationCount`.
   - Add lightweight aggregate queries to populate these new fields.
2. **Frontend UI (`zentomDashboard.html` / `.css`):**
   - Create a `<div class="telemetry-bar">` component containing these widgets.
   - Style them as compact, high-tech counters (e.g., green/red trend arrows).
3. **Frontend Logic (`zentomDashboard.js`):**
   - Implement the `lastRefreshed` timestamp update inside the wire provisioning block.
   - Map the new summary fields to the template.
