# SentinelFlow v1.2.0 Production Deployment Runbook

This document outlines the official step-by-step production deployment runbook for SentinelFlow v1.2.0.

---

## 1. Purpose
This runbook defines the exact sequence of pre-deployment, deployment, post-deployment validation, smoke testing, and fallback rollback procedures for releasing SentinelFlow v1.2.0 to the production environment.

---

## 2. Release Version
* **Release Version**: `v1.2.0`
* **Release Type**: Minor Feature Release (Telemetry Anomaly Predictions & Governed Auto-Heal Engine)

---

## 3. Source RC Tag
* **Source Release Candidate Tag**: `v1.2.0-rc.1`
* **Source Branch**: `codex-sentinelflow-marketing-zentom-bot`
* **VCS Reference**: Pushed and verified at `origin`.

---

## 4. Production Target Org
* **Target Environment**: Production Org (`vjprod@asap.com`)
* **API Version**: 60.0

---

## 5. Pre-Deployment Checklist
Prior to starting the deployment, verify the following gates are cleared:
1. [ ] **Scope Freeze**: Confirm no new feature code has been merged since `v1.2.0-rc.1`.
2. [ ] **Sandbox Validation**: Ensure regression testing validation is complete ([v1.2.0-release-candidate-validation.md](file:///d:/TomCodeX%20Inc/SentinelFlow/docs/v1.2.0-release-candidate-validation.md)).
3. [ ] **Security Sign-off**: Verify the security review is complete ([v1.2.0-security-fls-crud-validation.md](file:///d:/TomCodeX%20Inc/SentinelFlow/docs/v1.2.0-security-fls-crud-validation.md)).
4. [ ] **Backup Configuration**: Take a local backup of the current production metadata including custom settings, custom metadata records, page layouts, and permission sets.
5. [ ] **Kill Switch Active**: Ensure the global kill switch is prepared for immediate deactivation if needed.

---

## 6. Deployment Steps

### Step 1: Deploy Validation (Dry Run)
Before executing the live release, run a deployment validation check against production to verify unit tests compile and run:
```bash
sf project deploy validate --test-level RunLocalTests --target-org vjprod@asap.com
```

### Step 2: Deploy Production Package
Deploy the metadata changes from the repository codebase:
```bash
sf project deploy start --test-level RunLocalTests --target-org vjprod@asap.com
```

### Step 3: Custom Settings Update
Verify the custom settings and metadata in production for hourly engineering and case baseline overrides:
* `Engineering_Hourly_Rate` (Default: `80.0`)
* `Manual_Resolution_Hours` (Default: `2.0`)
* `Baseline_MTTR_Minutes` (Default: `240.0`)
* `Cost_Per_Support_Case` (Default: `150.0`)

---

## 7. Validation Steps
Verify that the deployed package matches the source repository parameters:
1. **Apex Tests**: Run production-level unit tests and confirm `100%` pass rate on all 422 tests:
   ```bash
   sf apex run test --test-level RunLocalTests -o vjprod@asap.com -r human
   ```
2. **Permission Sets**: Ensure FLS fields on the custom objects `Sentinel_Anomaly_Signal__c` and `Sentinel_Prediction__c` are assigned to the `SentinelFlow_Admin` and `SentinelFlow_Operator` roles.

---

## 8. Smoke Test Plan
Execute the following manual smoke tests in production:
1. **Low-Risk Telemetry Simulation**: Execute a dry-run anomaly script (`simulate_pilot_scenario_a.apex` in dry-run mode) to verify that the scoring service correctly evaluates metrics and outputs expected warnings.
2. **Dashboard Console Check**: Access the SRE Dashboard and verify that the glassmorphic KPI cards (average AI confidence, error logs counter) refresh correctly.
3. **Guardian Gate Lock**: Attempt to run an execution sequence with a simulated risk score $\ge 40.0\%$, verifying that the system blocks the action and puts it in the human approval queue.
4. **Audit Logger Check**: Confirm that all transactions and blocks successfully insert compliance logs into `Sentinel_Audit_Log__c`.

---

## 9. Rollback Plan
If any critical release blockers or unexpected errors occur during deployment validation or smoke testing, follow the rollback sequence:
1. **Global Deactivation**: Instantly toggle custom setting `Auto_Heal_Active` to `0.0` or deactivate settings to block all auto-heal triggers.
2. **Metadata Revert**: Redeploy the pre-deployment backup package to revert Apex classes, LWC components, and custom object schemas.
3. **Re-run Test Suite**: Validate that the rollback deployment successfully compiles and passes tests.
4. **Notification**: Send incident notifications to all Slack/Teams channels alerting operators of the reversion.

---

## 10. Communication Plan
* **Deployment Notification**: Send alert to SRE ops channels 24 hours prior to release window.
* **Maintenance Banner**: Enable dashboard maintenance indicators during deployment.
* **Release Confirmation**: Inform key stakeholders and operators when the deployment is confirmed complete and passes all smoke tests.

---

## 11. Go / No-Go Checkpoint
* **Validation Gate**: All 422 unit tests must pass.
* **FLS Gate**: Admin and Operator permissions must be fully active.
* **Smoke Gate**: Scenario validations and dashboard loading must display zero exceptions.

---

## 12. Success Criteria
* **Test Success**: `100%` of unit tests passed (422/422 Apex unit tests passed).
* **System Headroom**: Telemetry polling limits remain within 50% Salesforce governor boundaries.
* **Compliance Logs**: All operations, approvals, and blocks are chronological and verified in the audit trail.
* **Security Compliance**: Zero unauthorized DML queries or permission bypasses.
