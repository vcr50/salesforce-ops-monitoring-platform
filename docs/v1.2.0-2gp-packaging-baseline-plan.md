This document defines the Milestone 71 packaging baseline for staging SentinelFlow + Zentom AI v1.2.0 as a Salesforce Second-Generation Managed Package (2GP) for AppExchange security review preparation.

Milestone 71 starts the AppExchange packaging phase after the v1.2.0 enterprise stable release has been merged into `main` and tagged. The purpose of this plan is to define the source baseline, package scope, access model, validation checks, and version creation sequence before any 2GP package commands are run.

## 7. Package Type Decision

- Package type: Second-Generation Managed Package (2GP)
- Distribution intent: AppExchange managed package

## 8. Namespace / Dev Hub Assumptions

- Dev Hub is available and authenticated before package commands run.
- Package namespace is reserved and linked to the Dev Hub.
- Namespace ownership is aligned with the AppExchange publisher account.
- Scratch org definition and package aliases are reviewed before package creation.
- No package creation command should run until the Dev Hub alias and namespace linkage are explicitly confirmed.

---

## 9. Metadata Packaging Scope

Initial packaging scope includes the production Salesforce metadata required for SentinelFlow + Zentom AI v1.2.0:

- Apex classes and triggers under `force-app/main/default/classes` and `force-app/main/default/triggers`
- Lightning Web Components under `force-app/main/default/lwc`
- Custom objects, fields, list views, and platform events under `force-app/main/default/objects`
- Permission sets required for admin, operator, viewer, portal, subscription, and runtime access
- Custom metadata types and records required for feature flags, runbooks, and settings
- Named credentials, remote site settings, tabs, applications, pages, and supporting static resources required for runtime use
- Manifest and project configuration needed to validate package membership

Permission set strategy remains least privilege: keep admin, operator, viewer, portal support, portal viewer, runtime admin, and subscription admin access separated; preserve CRUD/FLS enforcement; and confirm package access does not expose audit log mutation paths to non-admin roles.

---

## 10. Excluded Metadata

The following should be excluded from the package candidate unless explicitly approved:

- Local test outputs, coverage artifacts, scratch folders, and temporary files
- Development-only scripts not required at subscriber runtime
- Local `.env` files, credentials, auth URLs, generated logs, and cache folders
- Non-runtime website prototypes, backup documents, and one-off diagnostic utilities
- Org-specific destructive changes unless required for package validation and documented separately

## 12. Package Version Creation Steps

1. Switch to `main` and pull the latest remote state.
2. Confirm current branch and commit: `git branch --show-current` and `git rev-parse HEAD`.
3. Confirm release tag: `git rev-parse v1.2.0`.
4. Confirm Dev Hub authentication and namespace linkage.
5. Review `sfdx-project.json` package definition and package directory.
6. Run source format validation.
7. Create the 2GP package version candidate from `main`.
8. Capture package version ID, subscriber package version ID, build logs, and validation output.
9. Install the package version into a clean validation org.
10. Run post-install smoke validation and `RunLocalTests`.
11. Document package version results and AppExchange readiness deltas.

## 13. Known Risks

- Namespace or Dev Hub linkage may not yet be verified in the local environment.
- Some metadata may require package-specific exclusions or refactoring after first package validation.
- Org-specific Experience Cloud, named credential, or remote site settings may need subscriber-safe defaults.
- Salesforce validation jobs depend on repository secrets and may skip by design when secrets are unavailable.
- Existing documentation and non-runtime assets may need stricter package boundary review before final submission.
- The product release tag intentionally points to `c869da7`, while current `main` includes later CI and documentation hardening at `e9d2bb4`.
