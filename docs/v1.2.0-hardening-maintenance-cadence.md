## 4. Weekly Health Review

### Schedule
- **Day**: Every Monday
- **Duration**: 30 minutes
- **Owner**: Alex Rivera (SRE Lead)
- **Attendees**: SRE on-duty, Engineering Lead (optional)

### Checklist

| # | Item | Source | Action |
|---|------|--------|--------|
| 1 | Query `Sentinel_Error_Log__c` for uncaught exceptions | Apex Error Logs | Triage any new entries |
| 2 | Verify `SentinelIncidentTrigger` compiles and fires | Trigger Health | Confirm no deployment drift |
| 3 | Check CometD streaming telemetry indicator | Dashboard | Verify live streaming pill is active |
| 4 | Review OTS (Operational Trust Score) | Prediction Engine | Confirm ≥ 90% |
| 5 | Review prediction noise dismissal count | Prediction Engine | Flag if dismissals > 5% of predictions |
| 6 | Check Guardian Gate approval queue backlog | Guardian Gate | Ensure zero backlog accumulation |
| 7 | Check Auto-Heal execution logs | Auto-Heal | Verify zero lock errors, rollbacks, retry loops |
| 8 | Verify audit log count matches incident transitions | Audit Log | Confirm referential integrity |
| 9 | Spot-check cost savings widget rendering | Dashboard | Verify "Estimated" wording and accuracy |
| 10 | Review operator feedback / alert fatigue signals | Operator Survey | Flag any emerging concerns |

### Escalation Rules
- Any P0/P1 finding → Immediate triage (see Section 7: Patch Trigger Criteria)
- Any P2 finding → Log in issue tracker, schedule for next weekly review
- Clean review → Document "No issues" in weekly log

## 7. Patch Trigger Criteria

A patch release (v1.2.1) is triggered **only** when one or more of the following conditions are met:

| # | Trigger | Severity | SLA | Action |
|---|---------|----------|-----|--------|
| 1 | **P0 — Critical outage or security breach** | Critical | 15 min triage / 4 hr fix | Immediate patch + hotfix deploy |
| 2 | **P1 — Core feature failure or data corruption** | High | 1 hr triage / 24 hr fix | Priority patch release |
| 3 | **P2 — Non-blocking UI or calibration drift** | Medium | 4 hr triage / next patch | Batched into next scheduled patch |
| 4 | **Security vulnerability discovered** | Critical–High | Immediate triage | Emergency security patch |
| 5 | **Compliance blocker (SOX/SOC2/audit)** | High | 24 hr triage | Compliance remediation patch |
| 6 | **Governor limit breach in production** | High | 1 hr triage | Performance fix patch |

### Patch Decision Flow

```
Issue Discovered
  │
  ├─ P0 / Security / Compliance → Immediate Patch
  │
  ├─ P1 → Priority Patch (within 24 hrs)
  │
  ├─ P2 → Batch into next scheduled patch
  │
  └─ Low / Observational → Log and defer to quarterly review
```

> [!CAUTION]
> **No patch release shall include new features.** Patches are strictly limited to fixes, security remediations, and compliance corrections.
