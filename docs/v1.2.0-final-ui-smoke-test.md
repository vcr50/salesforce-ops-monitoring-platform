# SentinelFlow + Zentom AI v1.2.0 Final UI Smoke Test

## 1. Purpose

Milestone 71B-7 verifies that the AppExchange-facing SentinelFlow UI is clean, readable, and free from unfinished placeholder experiences before any 2GP package version candidate is created.

## 2. Test Environment

- Source branch: `main`
- Test type: local source-level UI smoke test
- Components reviewed:
  - `force-app/main/default/lwc/sentinelFlowBetaAppShell`
  - `force-app/main/default/lwc/sentinelFlowPortalSettings`
- Runtime note: no Salesforce browser runtime was launched during this smoke test. The validation is based on packaged LWC source, route guards, markup, and CSS rules.

## 3. Navigation Validation

Default visible sidebar navigation exposes functional product pages:

- Dashboard
- Incidents
- Approvals
- Actions
- Reports
- Integrations
- Settings

Navigation handler behavior was verified in source:

- `navigate(event)` reads `data-page`.
- Requested pages are checked through `isPageEnabled(pageName)`.
- Disabled future routes fall back to `incidents`.
- Mobile sidebar closes after navigation.

Verdict: Pass.

## 4. Hidden Placeholder Tab Validation

Future modules remain in source only behind default-off flags:

- `showCases: false`
- `showPolicies: false`
- `showRunbooks: false`

Sidebar templates render Cases, Policies, and Runbooks only when their flags are true.

Validation checks:

- Cases tab hidden by default: Pass.
- Policies tab hidden by default: Pass.
- Runbooks tab hidden by default: Pass.
- No `Coming Soon` strings in reviewed LWC source: Pass.
- Disabled future routes fall back safely: Pass.

## 5. Settings Readability Validation

Settings UI cleanup from 71B-6 was verified in `sentinelFlowPortalSettings.css`.

Validated improvements:

- Light-mode settings variables are present.
- Card backgrounds use readable light surfaces.
- Labels and descriptions use readable text colors.
- Inputs, selects, number fields, and webhook fields use readable backgrounds and borders.
- Active Settings tabs have clear visual treatment.
- Buttons and secondary actions have clear contrast.
- Focus-visible states are present for tabs, buttons, and form controls.

Verdict: Pass.

## 6. Incidents Page Validation

Dashboard and operational links route to functional Incidents flow where needed:

- Incident CTAs use `data-page="incidents"`.
- Runbook references from dashboard were remediated to route to Incidents instead of a placeholder Runbooks page.
- Disabled future routes also fall back to Incidents.

Verdict: Pass.

## 7. Dashboard / Command Center Validation

Command Center remains the default page (`currentPage = 'command'`).

Validated behavior:

- Dashboard navigation is visible and functional.
- Dashboard links route to functional pages including Approvals, Incidents, Actions, and Integrations.
- No dashboard CTA routes to a visible unfinished placeholder module.

Verdict: Pass.

## 8. Mobile / Responsive Validation

Responsive CSS rules are present for the app shell and Settings component.

Validated source coverage:

- App shell includes responsive rules for tablet and mobile widths.
- Settings page includes responsive rules at `900px`, `720px`, and `480px`.
- Settings form grid collapses to a single column on smaller screens.
- Settings tabs collapse from four columns to two columns and then one column.
- Endpoint rows and subscription metrics stack on smaller screens.

Verdict: Pass by source inspection. Browser/device screenshot validation remains recommended in a live Salesforce org.

## 9. Accessibility / Focus State Validation

Validated source coverage:

- App shell includes global `:focus-visible` rules for buttons, links, inputs, selects, and textareas.
- Settings component includes component-level `:focus-visible` rules for tabs, primary/secondary buttons, small action buttons, and form controls.
- Active tab styling is visually distinct.
- Major low-contrast Settings light-mode issues from the audit were remediated.

Verdict: Pass by source inspection.

## 10. Issues Found

No blocking UI issues were found in the reviewed source.

Non-blocking follow-up:

- Run a live Salesforce org screenshot pass before final AppExchange submission materials are captured.

## 11. Final UI Verdict

Pass for Milestone 71B-7 source-level final UI smoke test.

The AppExchange-facing UI source is clean enough to proceed once the non-UI 2GP packaging blockers are resolved:

- No visible `Coming Soon` modules in default navigation.
- Cases, Policies, and Runbooks are hidden by default.
- Disabled future routes fall back safely.
- Settings readability issue is remediated.
- Functional navigation routes remain available for default product workflows.
