# SentinelFlow v1.2.0 Post-Release Monitoring Plan

This document outlines the official post-release monitoring and health check plan for SentinelFlow v1.2.0.

---

## 1. Purpose
The purpose of this plan is to establish a rigorous, structured protocol for monitoring the health, stability, accuracy, and security of SentinelFlow v1.2.0 during the stabilization window immediately following the production release.

---

## 2. Production Monitoring Scope
Monitoring covers the entire v1.2.0 package suite including:
* **Anomaly Telemetry Ingestion**: Telemetry metrics collections on CPU, APEX error velocity, and retry spikes.
* **Zentom AI Prediction Engine**: Explanation templates compilation and probability scoring calculations.
* **Guardian Gate Approvals**: Escalation queue records and operator permissions validation.
* **Auto-Heal Execution**: Action center Task/Case executions, savepoint rollbacks, and retry ceilings.
* **Cost & Value Dashboard**: Visual widget calculations based on Custom Metadata thresholds.
* **GRC Compliance Logging**: Trace UUID transaction logs in `Sentinel_Audit_Log__c`.

---

## 3. First 7-Day Monitoring Window
The stabilization window runs for a continuous **7 days** post-release:
* **Triage Lead**: Alex Rivera (SRE Lead)
* **Weekly Review Checkpoint**: End of Day 7
* **Triage Sync Frequency**: Daily 15-minute SRE standup reviewing predictions and incident queues.

---

## 4. P0 / P1 / P2 Issue Tracking
All issues discovered during the monitoring window must be classified and resolved according to SLA protocols:
* **P0 (Critical Outage / Security Breach)**:
  * *Triage SLA*: Immediate (within 15 minutes).
  * *Fix SLA*: Under 4 hours.
  * *Action*: Toggle the `Auto_Heal_Active` kill switch to `0.0`, initiate rollback metadata deploy if needed, and alert SRE channels.
* **P1 (Core Feature Failure / Data Corruption)**:
  * *Triage SLA*: Within 1 hour.
  * *Fix SLA*: Under 24 hours.
* **P2 (Non-blocking / UI / Calibration Drift)**:
  * *Triage SLA*: Within 4 hours.
  * *Fix SLA*: Planned for next weekly calibration patch.

---

## 5. Auto-Heal Execution Monitoring
Track the health of the recovery pipeline daily:
* **Concurrency Locks**: Monitor query errors for row locking (`SELECT FOR UPDATE` blocks).
* **Rollback Frequency**: Trace rollbacks (`ROLLBACK_EXECUTED`) to identify code exceptions.
* **Ceiling Blocks**: Log incidents flagged with `RETRY_EXHAUSTED` limits (max 3 failed attempts).

---

## 6. Prediction Accuracy Monitoring
Calibrate Zentom AI models using rolling Operational Trust Scores (OTS):
* **Noise Dismissals**: Check Pareto distributions of operator dismissals and noisy alerts.
* **Threshold Drift**: Back-test scoring precision (target $\ge 90\%$) and recall (target $\ge 92\%$).
* **RCA Auditing**: Execute lookback checks on missed anomalies (false negatives) using `SentinelPredictionRcaQueueable.cls`.

---

## 7. Guardian Gate Approval Monitoring
Verify human-in-the-loop security boundaries:
* **Queue Backlogs**: Monitor incidents pending approval.
* **Bypass Auditing**: Verify that zero actions are executed without human operator validation for incidents with anomaly scores $\ge 40.0\%$.

---

## 8. Audit Log Verification
Validate compliance database integrity:
* Run daily queries checking trace UUID mapping completeness on `Sentinel_Audit_Log__c`.
* Ensure referential integrity fallbacks correctly preserve audit records when incidents are locked or deleted.

---

## 9. Cost Savings Widget Verification
* Crosscheck that visual LWC dashboard charts correctly calculate hours saved and avoided cases based on active Custom Metadata settings.
* Verify baseline engineering hourly rates ($80.0/hr) and case cost settings ($150.0/case).

---

## 10. Daily Health Checklist
Every morning, the SRE on-duty must execute the following checklist:
1. [ ] **Apex Error Logs**: Query `Sentinel_Error_Log__c` for package uncaught exceptions.
2. [ ] **Trigger Health**: Verify `SentinelIncidentTrigger` and execution services compile.
3. [ ] **Streaming Telemetry**: Check header indicator pulses to confirm CometD streaming telemetry is connected.
4. [ ] **OTS Calculations**: Ensure Operational Trust Score is calculated and displayed.
5. [ ] **Audit Trail Integrity**: Verify log counts match incident transitions.

---

## 11. Stabilization Exit Criteria
Milestone 66 stabilization phase is complete and v1.2.0 is signed off for General Availability (GA) when:
1. **Zero Open P0/P1 Issues**: All critical release bugs are resolved.
2. **OTS Gate Cleared**: Rolling Operational Trust Score remains $\ge 90.0\%$.
3. **Zero Lock Exceptions**: No query concurrency or database lock errors are logged.
4. **Complete Audit Logs**: All compliance entries are verified complete.

---

## 12. Stabilization Scope Rule

> [!IMPORTANT]
> **No new features are permitted during the monitoring window.** Engineering activity is strictly restricted to P0/P1/P2 fixes, security adjustments, and production stabilization corrections.
